# Hull C Lua and JavaScript audit

Date: 2026-10-10. Baseline: `54a7e976252e6909806dbfdb3c6b0a2f0bdafd54`.
The C, Lua and JavaScript audit workflows identified nine issues: one high,
seven medium and one low. The findings below describe the baseline behavior;
the checklist records implementation and verification separately.

## Lifetime ownership and concurrency

Reviewed boot policy sealing and arena teardown preserve consumers' lifetimes.
Reviewed mmap references, WASM submission pins and JS image/GPU guards retain
borrowed buffers. Worker inputs, cancellation, WASM reservations and GPU
mutexes preserve their reviewed ownership rules. The confirmed concurrency
defect is C1; no additional defect was confirmed in these reviewed paths.

The audit also identified a separate completion-queue allocation failure in
`src/hull/async/poll.c`: completed work could lose its callback and leave a
coroutine parked or an operation leaked. This architectural follow-up was
separate from the nine findings above and was fixed on 2026-10-11, as recorded
below.

## Fix verification

### HTTP-free CLI readiness follow-up (2026-10-12)

Release-readiness checks on merged commit `34fc7d5d` found two additional CLI
blockers. JS asynchronous `app.main` rejected a NULL HTTP server before using
its existing poll context; CLI app initialization also omitted the already
created worker pool, so neither runtime registered the worker module before
loading the app.

JS main now checks its async context and treats a failed or prematurely stopped
loop as failure. Detached sleep timers are tracked, cancelled and released on
early main failure and runtime teardown, preventing QuickJS promise-reference
leaks. CLI app-context initialization receives the borrowed worker pool before
module registration; the runner retains ownership and its shutdown order.

Four runtime tests cover serverless async main, early loop stop, a throwing main
with an outstanding sleep and runtime teardown with an unawaited sleep. The
six-case `tests/e2e_cli_poll.sh` runs actual Lua and JS CLI apps with HTTP
disabled, exercising 32 timer waits, worker dispatches and async DB queries per
run, exit statuses 0/7, and JS fulfillment/rejection with a pending timer.
Both suites passed locally. The HTTP-free build-flavor CI job now runs the
end-to-end suite rather than only a synchronous Lua smoke app.

### Completion-queue follow-up (2026-10-11)

The poll backend now reserves a completion record before accepting pool work
or suspending an operation. Allocation failure rejects admission, retaining
caller ownership. Accepted completions use a linked queue and enqueue without
allocation. A failed tick retains queued callbacks for a later successful tick.
Cancellation invalidates entries in queued and nested drain batches before an
op can be reused. Deadline delivery withdraws a resume queued during the same
tick before calling user code. Duplicate completion calls are coalesced.

Pool shutdown joins running workers and cancels pending ring entries without
allocating a snapshot. Reserved records are released by delivery, cancellation,
deadline failure or queue teardown. The documented event-loop-only contract for
`op_complete` is unchanged.

Local verification: all 16 existing poll-backend tests and nine new allocation
fault-injection/lifetime tests passed with Cosmopolitan. The new suite counts
live backend allocations and checks that teardown releases every allocation.
It runs in the normal test sweep and the targeted TSan sweep.

## Release acceptance follow-up (2026-10-12)

Signed candidate `v0.16.0-rc2` was published from `8c23271c` after all 72
merged-main CI jobs passed. Acceptance found the following issues before
final-release promotion:

1. The staging helpers mirror six runtime/signature assets but omit the
   signed `hull.version` asset required by the current updater. Windows
   self-update and ACL rollback fail before reaching the swap. Download,
   verify and mirror this asset whenever the signed manifest names it;
   retain compatibility with the historical v0.13.0 baseline.
2. The installed-binary signature smoke generates `build/platform.sig` in
   its temporary directory but does not explicitly pass it to `hull build`.
   The audited build command intentionally stopped discovering signatures
   from the working directory. Pass `--platform-sig` for the generated test
   signature; retain the signature assertions.
3. Windows acceptance's non-admin Lua, JS and nested-module app builds fail
   during linking without compiler diagnostics. The tool-path sandbox rejects
   nonexistent output files supplied as drive-letter/backslash paths before
   invoking the compiler: its fallback ancestor walk splits only on `/`.
   Normalize Windows paths before walking, retaining traversal and stream
   checks. The new Windows regression test fails before this fix and passes
   afterward; all seven path-sandbox tests pass. A separate Windows
   source-build run also encountered Cosmopolitan `collect2` spawn errors and
   was retried.
4. The platform signer prints `wrote build/platform.sig` even when writing
   fails. Its embedded-library path creates `build/`, but the sandbox's
   missing-path canonicalizer rejects the empty trailing component. Accept
   a directory's trailing separator during ancestor resolution, retain the
   traversal checks, and make the signer fail if the signature cannot be
   written. The preliminary corrected-harness run `38285962737` exposed this.

Evidence: automated acceptance run `38279434074`, Windows acceptance run
`38279437414`, and additional Windows source-build run `38271055108`.
The candidate remains a prerelease until these acceptance checks pass.
