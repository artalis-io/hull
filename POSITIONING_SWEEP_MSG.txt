docs: add POSITIONING.md, align messaging, archive obsolete, em-dash sweep

  Five threads in one commit, all about post-v0.1.4 documentation
  hygiene: making the positioning consistent everywhere, removing
  typography drift across every prose file, and clearing out
  historical docs that no longer reflect current state.

  1. docs/POSITIONING.md (new, 153 lines). Standalone messaging
     reference encoding the canonical thesis, descriptor, target
     audiences, tone, vocabulary table, geographic positioning,
     typography rules, surface-update cadence, and authoring
     checklist. Lives separately from MANIFESTO.md because the two
     do different jobs: MANIFESTO is the long-form WHY (narrative,
     philosophical), POSITIONING is the operational reference
     (terse, tabular, optimized for lookups). Any future writer
     (human or AI) reads POSITIONING before editing user-facing
     copy; the cascade order is documented in the file itself.

  2. Positioning alignment across pre-existing positioning surfaces:

     - docs/MANIFESTO.md. Title vocabulary unified: "A Capability-
       Secure Runtime for Agent-Native, Local-First Applications"
       becomes "A Hardened, Capability-Secure Runtime for AI-Native
       Systems." Added a 3-line callout under the title with the
       canonical thesis and a pointer to POSITIONING.md.

     - docs/INVESTORS.md. Added the same thesis + descriptor callout
       at the top. Fixed "secure runtime" (vocab violation, NEVER
       column) and "agent-generated" (should be AI-generated) in
       the "Sharper thesis" line. Refreshed the Status section
       (stale "v0.1.0 feature-complete and approaching release")
       to reflect actual current state: v0.1.4 shipped on 2026-05-28,
       all artifacts live on GitHub Releases, the embedded gethull
       release key is operational. Updated capital-allocation
       bullets accordingly (v0.1.0 release engineering -> v1.0).

     - AGENTS.md opening line updated to the canonical descriptor.

     - docs/release_signing.md status line updated from
       "Design draft, pre-v0.1.0" to "Shipped (as of v0.1.3)."
       The embedded gethull release key has been live since v0.1.3;
       the doc was lying about its own status.

     - CLAUDE.md untouched in substance. Contributor reference.

     - docs/PERSONAS.md positioning untouched in substance. The
       personas already carry the value-prop organically through
       their stated reasons and quotes; injecting marketing-style
       framing on top would dilute them.

     - The remaining 14 docs (agent_guide, architecture,
       backend_vtables, benchmark, cli_mode, README, roadmap,
       roadmap_next, security, stability, tools_install, tui_mode,
       wamr_architecture, archive/README) were scanned for vocabulary
       drift. Zero substantive issues found. These are technical
       reference and design docs that describe specific subsystems
       or contracts, not Hull-wide positioning claims. They stayed
       in their lanes; they did not need vocabulary updates.

  3. Em-dash sweep across every prose file in the repo:
     README.md, AGENTS.md, CLAUDE.md, docs/MANIFESTO.md,
     docs/INVESTORS.md, docs/PERSONAS.md, docs/POSITIONING.md,
     docs/agent_guide.md, docs/architecture.md, docs/backend_vtables.md,
     docs/benchmark.md, docs/cli_mode.md, docs/README.md,
     docs/release_signing.md, docs/roadmap.md, docs/roadmap_next.md,
     docs/security.md, docs/stability.md, docs/tools_install.md,
     docs/tui_mode.md, docs/wamr_architecture.md, site/index.html,
     site/verify.html.

     1100-plus em-dashes replaced with period + capitalize for
     between-clause breaks, parentheses for parentheticals, colons
     for elaborations. Same pattern as the prior precedent in
     commit 6b6f394. Two UI placeholder em-dashes in verify.html
     status badges became middle dots, preserving the visual
     "no value" semantics without typography drift.

     One intentional em-dash remains: docs/POSITIONING.md line 109
     where the typography rule itself documents the character
     ("No em-dashes (`—`)"). Meta-reference, intentional.

     Em-dashes in C source code, completions/, and other developer-
     internal files are out of scope. This sweep targets prose only.

  4. Documentation archive sweep. Five files moved out of docs/ root
     into docs/archive/ because they no longer represent the current
     state of record:

       docs/audit_2026_05_15.md                  -> archive/audits/
       docs/audit_2026_05_15_phase6.md           -> archive/audits/
       docs/audit_2026_05_15_phase6_reaudit.md   -> archive/audits/
       docs/ASSESSMENT.md                        -> archive/
       docs/api_review.md                        -> archive/

     The three May 2026 audits are historical (findings closed).
     ASSESSMENT.md was a "approaching v0.1.0" snapshot; we shipped
     v0.1.4 today. api_review.md was a pre-v0.1.0 public-surface
     review; current contract lives in docs/stability.md.

     docs/archive/README.md updated with new entries in both the
     "Historical audits" table and a new "Historical assessments &
     reviews" section. The outdated "current audit reports at the
     top level of docs/" callout in the archive README was removed.

  5. No technical behavior changes. No API changes. No release
     required. Pure documentation alignment and typography hygiene.
