Hull Signature Verifier

Two flows: verify a Hull release binary against the embedded release public key, OR verify a Hull-built app bundle (package.sig) against the embedded platform key. Ed25519 verification runs in your browser via vendored TweetNaCl. no upload, no telemetry.

            What does this prove?
            

              
    
                
  • Gethull platform-sig. The per-arch SHA-256 of libhull_platform.a baked into the built app matches what gethull.dev signed at release time. The platform bytes were not swapped after release.
    • 
                
  • Per-app platform layer. The signature over the developer's platforms object is self-consistent with the embedded per-app pubkey. Developer-signed; not pinned to gethull.
    • 
                
  • App signature + key check. Binary + source + manifest + build info are authentic, signed by the stated developer. Does NOT prove the developer's intent is honest.
    • 
                
  • Binary hash match. The uploaded file is the one that was signed. Does NOT prove how it was built.
    • 
              

              

                Future improvements. Reproducible builds (anyone can re-build and compare binary_hash) and trusted build services (gethull.dev runs the build).
