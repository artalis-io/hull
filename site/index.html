Install & verify

One line to install. One line to verify.

The install script checks the SHA-256 manifest as it downloads the right binary for your OS and arch. hull verify-release then verifies the Ed25519 signature against the public key embedded in your local binary — no key distribution needed.

Linux x86_64 · macOS arm64 · Cosmopolitan APE fallback.

shell copy & paste 
# 1. Install. install.sh verifies the SHA-256 manifest as it downloads.
$ curl -fsSL https://gethull.dev/install.sh | sh
hull installed to ~/.local/bin/hull  (v0.1.0)

# 2. Verify the release signature (Ed25519, embedded pubkey).
$ hull verify-release hull.sha256 hull.sha256.sig
ok — signature valid

# 3. Inspect the toolchain.
$ hull doctor

The problem

Code you didn't write is running inside processes you do trust.

Tools, plugins, scripts, and AI-generated code increasingly land inside production processes with the full authority of the user running them. Filesystem access. Network access. Environment. Subprocess. Native loading.

Most runtimes treat this as a configuration problem. Hull treats it as a runtime problem. A handler can only reach capabilities that the application's manifest declared at load time — checked at a C boundary the script cannot cross.

Programmable tools without ambient authority.

Core principles

Seven properties, enforced from the bottom up.

Capability-declared access

Every filesystem path, host, environment variable, and module is declared in the manifest. Undeclared access doesn't error — it isn't there.

No ambient authority

Scripts cannot reach io, os, load, eval, Function(). The runtime's host environment is sealed.

Sealed bundles

hull build emits a single signed binary — app code, manifest, templates, migrations, and AOT WASM all live behind an Ed25519 signature.

W^X, no runtime codegen

Pages are writable or executable — never both. No JIT. No runtime dynamic code. WASM runs from AOT-compiled artifacts embedded at build time.

Local-first, one binary

No daemons. No package manager at runtime. The CA bundle, stdlib, runtimes, and WASM modules are all linked in. Boot on Linux, macOS, or Cosmopolitan APE.

Lua / QuickJS orchestration

Pick Lua 5.4 or QuickJS (ES2023). One runtime per app, selected by entry extension. Both call the same C capability layer through the same vtable.

Compute in WASM and WebGPU

CPU-heavy work runs as pure-function WASM plugins inside WAMR — no I/O imports, gas-metered execution, configurable memory caps. Parallel workloads dispatch to WebGPU compute shaders via wgpu-native (Vulkan, Metal, DX12) through the same capability boundary.

For agents

The runtime agents already live in.

Hull is built for both sides of the agent loop — hosting LLM-callable tools behind a manifest the model can't write to, and giving AI coding agents a structured CLI surface to read, test, and deploy Hull apps.

The runtime is the trust boundary. The manifest is the contract.

AGENTS.md MCP server

A sandbox for LLM-callable tools

The manifest is the tool's allowed surface. An LLM can write the handler but cannot expand the capabilities — declaring a new host, path, or env var means editing the manifest, which the runtime parses and validates before any user code runs. One Hull binary per tool gives you per-tool capability scoping for free.

  • Gas-metered Lua/JS · AOT WASM · deny-default everything.
  • Sealed signed binary — the agent can't smuggle native code in.
  • Kernel sandbox engaged at process start — ambient authority drops away.

How it works

One manifest. One handler. One sealed binary.

The manifest is parsed before any user code runs. Module imports are resolved against the declared set. Capability calls cross into C, where the declared allowlists are consulted on every operation.

Defense-in-depth flow

A capability call must pass the manifest gate, the C layer's allowlists, and the kernel sandbox. A denial at any layer is a hard stop — never a warning.

@group(0) @binding(0) var<storage, read_write> data: array<f32>;

@compute @workgroup_size(64)
fn main(@builtin(global_invocation_id) gid: vec3<u32>) {
    let i = gid.x;
    if (i >= arrayLength(&data)) { return; }
    data[i] = data[i] / 255.0;
}

app.post("/rank", function(req, res)
    local raw    = req:body()
    local scored = compute.call("score", raw)              -- WASM (WAMR AOT)
    local final  = gpu.async.dispatch("normalize", {       -- WebGPU (wgpu-native)
        buffers    = { { data = scored, usage = "readwrite" } },
        workgroups = { x = 256 },
        output     = 1,
    })
    res:json({ result = final })
end)

Security model

Defense in depth, designed in.

Three layers cooperate. The manifest restricts what code can name. The C capability layer enforces what those names can do. The kernel sandbox enforces what the process can do at all.

A violation at any layer is a hard stop, not a warning.

  • Guest-controlled memory is never executable
    W^X across the runtime. No JIT. WASM AOT artifacts are produced at build time and shipped read-only.
  • No undeclared filesystem, network, env, or process access
    Each capability resolves against the manifest allowlist at the C boundary. Path traversal is rejected via realpath ancestor checks.
  • No runtime package installation
    require and import resolve only against the embedded stdlib registry. Nothing is fetched at run time.
  • No dynamic native loading
    No dlopen, no FFI, no extension modules. The native surface is fixed at build time.
  • Kernel sandboxing on supported platforms
    Linux/Cosmo: pledge + unveil. macOS: sandbox_init with a manifest-derived profile.
Where Hull fits

Built for code you almost trust.

Agent tools

A bounded host for LLM-callable tools. The agent gets exactly the surface you declared, nothing else.
Local-first automation

Cron jobs, ETL scripts, file watchers. Run on a laptop or a VM with no daemons or dependencies.

Internal apps

Sealed web apps for admin panels and tools. SQLite, auth, sessions, CSRF, audit logging — in one binary.

Compute plugins

Ship WASM modules from any language or WebGPU shaders in WGSL. Gas-metered, memory-capped, AOT-compiled, callable from Lua/JS handlers.

Edge-deployable workflows

No package manager, no runtime dependencies. Drop the binary on a server, container, or APE-capable host.

Constrained AI-generated code

Execute generated handlers behind a manifest the model didn't write. The LLM cannot expand its own reach — declaring a new host, path, or env var means editing the manifest, which the runtime parses and validates before user code runs. Capability creep is impossible by construction.
