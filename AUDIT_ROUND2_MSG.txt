round-2 audit: reproducibility on Linux, vocab fixes, OG PNG, roadmap adds

  Second-pass audit found 6 real claim-vs-implementation gaps after
  the round-1 fixes shipped. All addressed below, plus a new finding
  surfaced mid-fix: the MANIFESTO's reproducibility claim was false
  on every platform, and only Linux can be made truly byte-identical.

  1. Reproducibility (the headline finding). Adding `make
     reproducible-check` exposed that two builds of the same app from
     the same hull binary differed by ~47 bytes per link. Diagnosis:
     macOS `ld64` embeds a random LC_UUID per link (16 bytes) plus
     downstream code-signature data (34 bytes); Linux `ld` embeds a
     random Build-ID GUID.

     Linux is fixable: `-Wl,--build-id=none` suppresses Build-ID
     cleanly (executables don't need it at runtime). Added to:
       - Makefile (for hull itself, Linux gate)
       - src/hull/compiler.c sys_link (for apps `hull build`
         produces, also Linux gate)

     macOS is NOT fixable at the link-flag layer: dyld REQUIRES
     LC_UUID and aborts the binary at startup with "missing LC_UUID
     load command" if `-Wl,-no_uuid` is used. The path forward
     (deterministic LC_UUID via deterministic input ordering, mostly
     `ar Drcs` patches to vendored Makefiles) is real work, tracked
     as roadmap §0.2.

     MANIFESTO line 108 updated to qualify the claim: "Reproducible
     builds (Linux). On macOS, builds differ by ~47 bytes per link;
     deterministic LC_UUID via input ordering tracked in roadmap."
     POSITIONING precision-notes section documents the platform
     split. The CI gate `reproducibility` job runs on Linux, where
     the claim is now true.

  2. "Zero system dependencies" wording was an overclaim. Embedded
     TinyCC removes the system-COMPILER requirement but the system
     LINKER (`cc`/`ld`) is still used for the link step. Fixed in:
       - docs/INVESTORS.md line 67
       - docs/MANIFESTO.md line 166 (dependency table)
       - LICENSING.md TCC entry
     New wording: "embedded TinyCC (so `hull build` does not require
     a separately-installed C compiler; the system linker is still
     used for the link step)."

  3. OG card was SVG-only. LinkedIn and Facebook don't render SVG
     OG images, so social previews from those platforms showed
     nothing. Generated `site/og-card.png` (1200x630, 78 KB) via
     rsvg-convert from the existing SVG; both index.html and
     verify.html now reference the PNG as og:image (with og:image:type
     image/png). SVG kept in the build for legacy / future use; PNG
     is the primary.

  4. agent_guide.md used "sandboxed" alone twice (POSITIONING vocab
     table forbids this: "Never say sandboxed (alone)"). Both
     instances paired with "capability-secure" / "the capability-
     secure runtime" instead. Line 47 (dev-server table cell) and
     line 352 (architecture diagram).

  5. New `make reproducible-check` target. Builds the null_app
     fixture twice with the same hull, cmps the outputs. Passes on
     Linux (byte-identical) once `-Wl,--build-id=none` is in effect;
     fails on macOS (LC_UUID delta) with a precise byte-count error
     message naming the cause. CI `reproducibility` job in
     `.github/workflows/ci.yml` now runs BOTH `make self-build`
     (bootstrap chain, all platforms) AND `make reproducible-check`
     (byte-identity, Linux-only).

  6. POSITIONING precision-notes section added. Documents the small
     truthful qualifications behind each canonical phrase:
       - "Single static binary" qualified for macOS libSystem
         (mandatory dynamic link per Apple since 10.7+).
       - "No telemetry, no phone-home" qualified for explicit
         user-invoked `hull update` and `hull tools install`.
       - "No auto-updates fetching code at build time" qualified
         for explicit `make fetch-*` targets.
       - "`hull build` requires no separately-installed C compiler"
         qualified for the system-linker dependency.
       - "Kernel-enforced boundary" qualified for env-var reads
         (C-layer only; kernel doesn't filter env syscalls).
       - "Reproducible builds" qualified for the macOS LC_UUID
         limitation.

     These are footnote-style qualifications, not the load-bearing
     claims. The "Always say" vocabulary table is unchanged; the
     precision notes are what to expand into when the audience
     asks for technical detail.

  7. Roadmap additions (`docs/roadmap_next.md`):
       - §0.1 `hull sbom` subcommand. Live, verifiable SBOM as a
         command, output formats: human / json / cyclonedx / spdx.
         Tier-1 credibility booster for compliance personas; closes
         the loop from a static LICENSING.md table to a binary you
         can run and audit. ~50-line subcommand + ~80-line static
         table + Makefile commit-hash bake-ins.
       - §0.2 Byte-reproducible builds on macOS. The work needed
         to make `make reproducible-check` pass on macOS too:
         vendored-Makefile patches to use `ar Drcs`, audit object
         embeds for entropy, add macOS to the CI reproducibility
         job. Medium effort; mostly upstream coordination.

  No technical behavior changes in the Hull runtime. Build pipeline
  becomes more deterministic on Linux. Apps `hull build` produces
  on Linux are now byte-identical between identical builds.
